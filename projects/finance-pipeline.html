BUILD NOTE / 02

Fetch — Personal Finance Pipeline

The useful data was already in the inbox

Python · Docker · GCP · Supabase

01

The problem

Bank transaction alerts already contain useful financial data, but an inbox is a poor place to query it. I built a way to turn those alerts into structured records without a paid banking API.

02

The constraints

The pipeline needs to work from email alerts, avoid counting the same message twice, and keep credentials out of the deployment. Raw email text also needs validation before it becomes a database record.

03

What I built

A Python pipeline fetches and parses transaction alerts from Gmail. Gemini extracts transaction details, each unique Gmail message ID is used to deduplicate entries, and the results become validated, queryable records in Supabase. The Dockerized script runs on Cloud Run; GitHub Actions and Artifact Registry handle delivery, with environment variables managed in Secret Manager.

04

What changes for the user

Transaction details become records that can be queried rather than messages that need to be searched one at a time. Reprocessing an email does not create another transaction for the same message.

05

Decisions & tradeoffs

Using the alerts avoids the paid banking API dependency. It also means this pipeline is only as complete as the alerts it receives; it is not a replacement for a bank’s authoritative transaction history.
